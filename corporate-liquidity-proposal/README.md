# Разблокировка активов и управление ликвидностью

[Открыть защищённое предложение](https://grarse.github.io/team-projects/corporate-liquidity-proposal/)

Отдельный проект общего каталога. Страница совместима с GitHub Pages: сервер и установка зависимостей не требуются. Для просмотра нужны выданные владельцем логин и пароль. Оба поля нечувствительны к регистру. При обновлении страницы потребуется войти заново; кнопка «Выйти» закрывает расшифрованные материалы.

## Что находится в репозитории

- `index.html`, `access.css`, `access.mjs` — страница входа.
- `protection.mjs`, `renderer.mjs` — расшифровка и запуск приложения в памяти браузера.
- `proposal.enc` — зашифрованные исходники, изображения, шрифты, документы и тесты содержимого. Открытого HTML с условиями предложения в Git нет.
- `scripts/` — команды для локальной работы; `tests/` — проверки защиты.

AES-256-GCM с новой солью и IV при каждой сборке; ключ получается из обоих полей через PBKDF2-SHA-256, 600 000 итераций. Пароль и ключ не записываются в репозиторий, URL или хранилище браузера и не отправляются на сервер. После входа материалы доступны посетителю в расшифрованном виде. Это клиентское шифрование, а не серверная авторизация: скачанный пакет допускает офлайн-подбор, поэтому стойкость зависит от пароля. Ранее сохранённые копии нельзя отозвать сменой пароля.

## Как вносить изменения

Нужен Node.js 22 или новее. Из папки проекта:

```sh
npm run unlock
```

Введите логин и пароль в терминале; пароль не отображается. Либо скопируйте `.env.example` в `.env.local` и заполните значения локально. Этот файл исключён из Git.

Исходники появятся в `.workspace/site/`, финансовые тесты — в `.workspace/tests/`. Редактируйте HTML, CSS и JS именно там. Повторная распаковка не перезаписывает уже существующую рабочую папку.

```sh
npm run test:content
npm run seal
npm test
npm run dev
```

Предпросмотр доступен на http://127.0.0.1:4175/. Он показывает последний зашифрованный пакет, поэтому после правок сначала выполните `npm run seal`. Локальная папка с открытыми исходниками через этот сервер не выдаётся.

Коммитьте обновлённый `proposal.enc` и, если менялась оболочка, её файлы. Не добавляйте `.workspace/` или `.env.local`. Публикация GitHub Pages использует тот же порядок, что и остальные проекты репозитория.

Ограничение упаковщика: ES-модули должны использовать литеральные относительные импорты без циклов. Встроенные зависимости текущего приложения этому соответствуют.

## Оформление и резервная история

Визуальная тема вдохновлена сайтом aton.ru: фиолетовый акцент, тёмные стеклянные поверхности, светлые карточки и плавная анимация. После распаковки оформление находится в `.workspace/site/aton.css`, компактная сетка и размеры — в `layout.css`, эффекты — в `glass.mjs`. Шрифт Inter хранится локально с лицензией OFL.

График сразу показывает сохранённую биржевую историю и проверяет свежие данные в фоне. Если источник недоступен, остаётся график с фактической датой котировок. Резервная история обновляется при пересборке, а не автоматически на GitHub Pages. Чтобы получить свежий снимок после распаковки, выполните `node .workspace/site/tools/refresh-market-snapshot.mjs`, затем `npm run test:content` и `npm run seal`. На Windows с корпоративными сертификатами добавьте флаг `--use-system-ca` к команде Node.js.
